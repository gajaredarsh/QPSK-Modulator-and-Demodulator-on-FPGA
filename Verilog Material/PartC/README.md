# Part C: receiver front end (Verilog)

LO + mixer + low-pass FIR + symbol timing / integrate-and-dump. Bit-exact against the team's fixed-point Python
(`rx_frontend.py`, `rx_backend_eval.py`). Carrier phase is assumed known (no Costas loop in this block).

## Files
| folder | what |
|---|---|
| `rtl/rx_frontend_top.v` | the block the rest of the design uses |
| `rtl/rx_nco.v` | wrapper around Part A's `nco.v` (same ROM, stepped by the RX sample strobe) |
| `rtl/rx_mixer.v` | `xi = r*cos`, `xq = -(r*sin)`, round, >>11, clip to 12 bit (2 DSP) |
| `rtl/fir_lpf.v` | 25-tap symmetric FIR, folded to 13 multipliers per rail (13 DSP each) |
| `rtl/symbol_sampler.v` | skip 12 samples of filter delay, then sum every 16 samples (integrate-and-dump), 16 bit |
| `rtl/qpsk_rx_params.vh` | GENERATED by `scripts/gen_rx_vectors.py`, do not edit |
| `scripts/gen_rx_vectors.py` | Python model -> header, taps, expected values |
| `tb/tb_rx_frontend.v` | every sample of mixer, FIR and symbol output vs Python, 3 input spacings |
| `tb/tb_chain.v` | Part A `tx_top` -> Part B `awgn_channel` -> Part C, vs the Python chain |
| `vectors/` | golden hex files (fir_coeffs.hex is what `fir_lpf.v` loads) |

## Run
    PARTA=<partA_rtl folder> PARTB=<part_b folder> [MODEL=<python_codes/fixed_point>] sh run_sim.sh
Needs Icarus Verilog. `MODEL` regenerates the vectors first (python3, numpy, scipy, matplotlib).
Run from Vivado: add `rtl/*.v` plus Part A's `nco.v`; keep `fir_coeffs.hex`, `lut_cos.hex`, `lut_sin.hex` as
design sources (the ROMs are loaded with `$readmemh`).

## Ports of rx_frontend_top
| port | width | meaning |
|---|---|---|
| clk, rst | 1 | 100 MHz, synchronous active-high. Use the SAME reset as the transmitter |
| in_valid, r_rx | 1, 12 signed | from `awgn_channel.out_valid` / `r_rx` (256 = amplitude 1.0) |
| y_i, y_q, y_valid | 12 signed, 1 | filtered samples (equal to the team's `d_yi.hex` / `d_yq.hex`) |
| i_hat, q_hat, sym_valid | 16 signed, 1 | one value per symbol (equal to `d_acc_i.hex` / `d_acc_q.hex`) |
| xi, xq, x_valid | 12 signed, 1 | mixer outputs, for debugging |

Part D decision rule (same as `rx_backend_eval.decide`): bit = (value < 0), order {I, Q}; I is `b0`, Q is `b1`, so
`{i_hat<0, q_hat<0}` equals Part A's `tx_bits`.

## Latency (clocks after the edge that samples `in_valid`, measured every sample by the testbench)
mixer 2, FIR output 8, `sym_valid` 9 after the last sample of the symbol window. `in_valid` may pulse every clock
or as slowly as you like (tested at every clock, every 4th, random gaps, and 1 Msample/s in the chain test).

## What Part D needs to know
* Symbol k out of `sym_valid` is TX symbol k (k-th symbol after reset). Match them by COUNTING (`sym_stb` on the
  TX side, `sym_valid` here), not by a fixed clock delay: when RX symbol k is ready the TX has already started
  1 symbol more (slow sample rates, e.g. 1 Msample/s) or 2 symbols more (a sample every clock). A 4-deep FIFO of
  `tx_bits` clocked by `sym_stb` and popped by `sym_valid` works for both.
* The first and last symbol are normally excluded from BER (`skip_first=1, skip_last=1` in Python).

## Things to settle with the team
1. **Header clash.** Part A and Part B each ship a `qpsk_params.vh` with the same include guard but different
   defines. Whichever is read first wins and the other part fails to compile. `run_sim.sh` builds a merged copy
   (no name overlaps); the project needs one merged `qpsk_params.vh`.
2. **Two NCOs, not one shared accumulator.** The RX NCO counts the receiver's own samples, so LO sample n is always
   paired with received sample n even though the channel and mixer delay the signal. Both NCOs are reset together
   and start at phase 0. If a receive sample were ever dropped they would drift apart; that is the point where a
   Costas loop would be needed.
3. **Where integrate-and-dump lives.** In the Python it is in `rx_backend_eval.py` (Part D's file), but the team plan
   says Part C hands over "sampled symbols", so it is here. If Part D already has one, drop `symbol_sampler.v` and
   take `y_i`, `y_q`, `y_valid`.
4. **Timing at 100 MHz is not verified.** Yosys synthesis for xc7 gives 28 DSP48E1, about 770 flip-flops, about 380
   logic cells and no errors, but only Vivado can report timing. The FIR is pipelined in 5 stages, so it should be
   comfortable; check the report after implementation.
